### 1.1 공정 순서

```
LCI > RT1 > OCV1 > C1 > C2 > OCV2 > HT1 > RT2 > OCV3 > C3 > C4 > OCV4 > HT2 > RT3 > OCV5
    > C5 > C6 > C7 > OCV6 > D1..D7 > OCV7 > RT4 > PRVT1 > RT5 > PRVT2 > RT6 > PRVT3
```

- `C`=충전, `D`=방전, `RT`=상온 에이징, `HT`=고온 에이징(60°C), `LCI`=Low Current Inspection
- 연속(휴지 없는) 충전 블록: `{C1,C2}` / `{C3,C4}` / `{C5,C6,C7}` · 연속 방전 블록: `{D1…D7}`

### 1.2 각 OCV 측정 시점의 SOC

| 측정 | SOC | 비고 |
|---|---|---|
| OCV1 | ≈0% | 충전 전 |
| OCV2 / OCV3 | 10% | **HT1 전 / 후 — matched-SOC** |
| OCV4 / OCV5 | 70% | **HT2 전 / 후 — matched-SOC** |
| OCV6 | 100% | 만충 |
| OCV7 | 30% | 방전 후 |
| PRVT1 / 2 / 3 | 30% | 전용 OCV 3점 |

## 2. 측정계 — **두 개의 서로 다른 시스템** ★

| 측정 | 장소 | 상태 |
|---|---|---|
| **중간 OCV #01~#07** | **충방전기 내부 (in-situ)** — 팬 가동 중 | **확정** |
| **전용 PRVT OCV #01~#03** | **별도 OCV 계측기** — 충방전기 밖 | **확정** |

**이 분리가 분석 설계의 핵심이다.**

- 중간 OCV 계열에는 **충방전기(팬 기류)의 지문**이 찍힌다.
- PRVT 계열에는 **OCV 계측기(지그·프로브·채널·주변 열환경)의 지문**이 찍힌다.
- `docv7 = PRVT1 − PRVT3` 이므로 **팬은 docv7에 직접 각인되지 않는다.**
  팬 → docv7 경로는 오직 **이월**뿐:
  `충전 중 기류 불균일 → 위치별 셀 온도차 → SEI·자기방전율 차이 → docv7`
  → **팬 서명이 docv7에서 발견되면 측정 아티팩트가 아니라 진짜 물리적 차이이며,
    보정 대상이 아니라 공정 개선 대상이다.**

### 2.2 ★ 중간 OCV 온도가 여는 것

중간 OCV는 **팬이 돌아가는 충방전기 안에서 측정**되고, 이제 **그 순간의 셀 온도**가 있다.

1. **팬 기류장의 직접 측정.** 전압은 SOC·용량·dU/dT가 섞이지만 **온도는 순수한 열장**이다.
   → 팬 서명 검증(F 그룹)을 **전압이 아니라 온도로 직접** 수행할 수 있다. 훨씬 깨끗하다.
2. **팬 기류장을 7번 독립 측정한 셈** (OCV#01~#07). **7장의 온도 필드가 서로 재현되면
   그 자체가 팬 가설의 증거**이고, 평균하면 SNR이 √7 개선된다.
3. **dU/dT 실측 가능.** 같은 셀·같은 SOC에서 온도와 전압을 동시에 얻으므로,
   트레이 내 회귀로 **SOC 단계별 dU/dT를 데이터에서 직접** 뽑을 수 있다.
4. **온도 보정 잔차 OCV.** 각 단계 전압에서 온도 몫을 제거한 "순수 전기화학" 성분을 분리
   → **단계별로 "구배 중 온도 몫 vs 비온도 몫"을 정량화**할 수 있다.
5. **S_A·S_B의 오염 제거.** `S_A = OCV2 − OCV3` 은 두 측정 시점의 온도가 다르면
   `dU/dT × ΔT` 만큼 오염된다. 이제 보정 가능 → **순수 자기방전 지표**가 된다.

### 2.3 ★ 타임스탬프가 여는 것

1. **구간 실제 경과시간 확보.** 지금까지 "간격 ≈1일, ≈2일"은 **추정값**이었다.
   실측 Δt를 쓰면 자기방전 지표를 **mV → mV/day (율)** 로 환산할 수 있다.
2. **세 지표의 통일 비교 가능.** S_A·S_B·S_C는 구간 길이·온도가 전부 다르다.
   시간·온도 정규화(아레니우스) 후에야 **등가 누설전류로 같은 자에 놓고 비교**할 수 있다.
3. **라인 정체 = 숨은 판정 편향.** 트레이마다 에이징 실제 시간이 다르면 전압 강하량도
   비례해 달라진다. 트레이별 mode 판정이 일부 상쇄하지만 완전하지 않다.
   → **"에이징 시간 편차 → 판정 편차"** 는 지금까지 아무도 확인하지 않은 축이다.
4. **시계열 진단(H 그룹) 가능.** 트레이 처리 순서 축이 생긴다.
5. 셀별 타임스탬프까지 있으면 **트레이 내 측정 순서(스캔) 효과**도 검사 가능.

### 2.3b 데이터 요청 목록 (우선순위)

> **원칙: "모든 스텝의 시작/종료 시각"으로 한 번에 받는다.** 나중에 재요청하는 비용이
> 지금 한 번에 받는 비용보다 훨씬 크다.

| 순위 | 항목 | 왜 필요한가 | 상태 |
|---|---|---|---|
| **1** | **에이징 스텝(HT1·HT2·RT1~RT6) 시작/종료 시각** ★★ | 자기방전은 에이징 중에 일어난다. **60°C 자기방전은 25°C의 10~30배.** OCV 측정 시각만으로는 총 Δt만 알 뿐 **그중 몇 시간이 60°C였는지 모른다.** 총 Δt가 같아도 HT가 길었던 트레이는 자기방전이 훨씬 크다 → `K3`·`K5`가 이것 없이는 반쪽 | 요청 필요 |
| **2** | **충·방전 스텝 시작/종료 시각** ★ | ① **CV가 지운 정보 복원**(§2.3c) ② **위치별 냉각 시상수 τ**(`F6`) ③ 열 노출 적분 | 요청 필요 |
| 3 | OCV 측정 시각 | 구간 Δt, 율(mV/day) 환산 | **확보** |
| 4 | 중간 OCV 셀 온도 | 팬 기류장 직접 측정 | **확보** |

> ⚠️ **충방전 시각으로는 HT1을 가를 수 없다.** 공정 순서가 `OCV2 > HT1 > RT2 > OCV3` 라
> 그 사이에 충방전 스텝이 없다. **에이징 스텝 자체의 시각이 따로 필요하다.**

**같이 확인할 것**: 시각이 **셀 단위인가 트레이 단위인가.**
충전은 채널별로 돌므로 셀 단위일 가능성이 높고, 그렇다면 §2.3c의 저항·용량 프록시가
**셀별**로 생겨 가치가 훨씬 크다. 트레이 단위면 τ·열노출은 되지만 셀별 프록시는 불가.

### 2.3c ★ 스텝 소요시간이 여는 것

**(1) CV가 지운 정보를 시간이 복원한다**

| 스텝 종료 조건 | 종료전압 | 소요시간 |
|---|---|---|
| CC 종료 (시간 기준) | **정보 있음** | 고정 → 정보 없음 |
| **CV 종료 (전압 기준)** | 강제 → **정보 없음** | **정보 있음** ★ |

원칙: **고정된 쪽은 버리고 가변인 쪽을 취한다.** 두 변수는 상보적이다.
정전압 종료 스텝을 분석에서 제외했던 이유(전압 강제)가 **소요시간으로는 해소**된다.
또한 **CV 구간 길이는 셀의 저항·용량 상태를 직접 반영**한다(저항↑ → CV↑, 용량↑ → CC↑)
→ DCIR 컬럼 없이 저항 지표를 하나 더 얻는다 (`D7`의 분극 프록시와 상보).

**(2) 위치별 냉각 시상수 τ(pos)** — 팬 가설의 직접 측정
온도만으로는 "지금 몇 도"까지다. **온도 + 시간이 있어야 "얼마나 빨리 식는가"** 를 얻는다.
팬 가설의 직접 예측: **팬 축 아래는 τ가 짧고, 팬 사이·배열 바깥은 τ가 길다.**
온도 스냅샷 비교(`F2`)보다 한 단계 강한 증거 — "온도가 다르다"가 아니라
**"열이 빠져나가는 속도 자체가 위치마다 다르다"** 를 보인다.

**(3) 열 노출 적분** — 아레니우스 열 이력은 온도 × 시간. duration 없이는 적분 불가.

**★ 새로 드러난 사실 2가지**

1. **`Work BOX_High Temp Aging` = 설비 메타데이터일 가능성.**
   그동안 "어느 설비인지 특정할 메타데이터가 없다"가 최대 난관이었다.
   챔버 ID가 맞다면 **`H3`(지문 군집화로 설비 역추정)을 추정이 아니라 실측으로 대체**할 수 있다.
   → **이 컬럼의 정체 확인 필요** (챔버 호기? 박스 번호? 슬롯?)

2. **상온 에이징이 9개(RT #01~#09)다.** 기존 문서의 공정 순서(RT1~RT6)와 다르다.
   → **`docv7 = PRVT1 − PRVT3` 구간이 RT #01~09 중 어느 번호인지 매핑 확인 필수.**
   틀리면 `K2`(율 환산)·`K5`(아레니우스)가 통째로 틀린다. 시각으로 역추적 가능.

3. **★★ 충·방전 박스 컬럼으로 호기(2/3/4/5)를 특정할 수 있다 — 매핑 확정 (2026-07-31)**.
   컬럼명(확인): `Work BOX_OCV #01~#07` · `Work BOX_Charge #NN`(에이징 박스와 동일 패턴).
   값 예: `CDC #MP2 -2-BOX #04-05 (1-4-5)` = **4호 · 4연 · 5단**. 문자열 3요소:
   - **호기**: `#MP{a}-{b}` 토큰 → 아래 표
   - **연(bay, 가로 1~14)** · **단(tier, 높이 1~10)**: `BOX #{연:02d}-{단:02d}` (`#04-05`=4연 5단)
   - 한 호기 랙 = **14연 × 10단**. 트레이는 그 중 한 슬롯을 차지 → **연·단은 랙 내 물리 위치**

   | 토큰 | 호기 | 팬 구성(§3.3) |
   |---|---|---|
   | `#MP1-2` | **2호** | 바닥 6×6 + 앞뒤 외기 |
   | `#MP2-1` | **3호** | 바닥 6×6 + 앞뒤 외기 |
   | `#MP2-2` | **4호** | 윗 4-5-4 + 바닥 4×4 + A쪽 외기 |
   | `#MP2-3` | **5호** | 윗 4-5-4 + 바닥 4×4 + L쪽 외기 |

   (`#MP1-1`=1호 추정이나 값 미제공 → 코드에서 unknown 처리). 박스가 **세션별로 갈린다**:
   `{C1,C2}` / `{C3,C4}` / `{C5,C6,C7,D1~D7}` — 한 트레이가 세션마다 다른 호기일 수 있으니
   **온도 지문은 그 스텝의 박스로 층화**한다.

   → **★ 팬 분석엔 `Work BOX_OCV #NN` 하나면 충분하다.** OCV 온도는 충방전기 안에서
   측정되는 F그룹 주력 온도장이고(§2.2), 각 OCV의 work box = 그 온도를 잰 호기·연·단이다.
   **실측 확인**: 한 트레이가 OCV1·2=4호 / OCV3·4=3호 / OCV5·6·7=5호 처럼 **세션마다 다른
   호기**를 거친다 → 같은 OCV#를 고정하고 호기로 가르면 **같은 SOC·같은 열상태에서 기류만
   다른 순수 대조**(자연 실험)가 된다. 반드시 **스텝별** 호기/연/단으로 층화할 것.
   → **연·단(랙 위치)은 추가 층화 축**: 측면외기 세기가 연에 따라 다를 수 있고(4·5호),
   높이(단)에 따른 열 성층도 가능 → 기류 가설을 한 단계 더 검정할 수 있다.
   코드 반영: `schema.parse_box()`(호기·연·단) / `charger_from_box()`,
   `Stage.box_col`(OCV) + `ThermStep.box_col`(충·방전),
   io_load `box_/charger_/bay_/tier_<step>` 컬럼.

### 3.0 ★ 좌표계 방향 — **확정** (2026-07 도면 주석)

```
        A  B  C  D  E  F  G  H  I  J  K  L     ← 알파벳 = 가로 = 열
     1 ┌────────────────────────────────┐
     2 │    ○      ○      ○      ○      │   팬 상단 밴드 4개
     3 │                                │
     4 ├────────────────────────────────┤
     5 │   ○    ○    ○    ○    ○        │   팬 중앙 밴드 5개
     6 │                                │
     7 │                                │
     8 ├────────────────────────────────┤
     9 │    ○      ○      ○      ○      │   팬 하단 밴드 4개
    10 │                                │
    11 │                                │
    12 └────────────────────────────────┘
     ↑ 숫자 = 세로 = 행 = **팬 3밴드가 쌓인 축**
```

- **알파벳 A~L = 열(가로)** · **숫자 1~12 = 행(세로)**
- **팬 3밴드는 숫자 축(세로)** 을 따라 쌓이고, 밴드 내 4-5-4 배열은 **알파벳 축(가로)**
- `Cell No` 규칙: `col = (n−1)//12+1` (A~L), `row = (n−1)%12+1` (1~12)
  → **A01→A02→…→A12→B01** 순으로 **세로로 먼저** 증가 (실데이터에서 `A6` 로 검증)

> ⚠️ **12×12 정사각이라 축을 뒤집어도 에러가 나지 않는다.** 전치된 채 조용히 계산되고,
> 팬 배열이 행/열 비대칭(3밴드 vs 4-5-4)이라 **`F1`·`F2` 결론이 정반대**가 된다.
> ※ **구 저장소 `tray_ocv` 문서에는 "알파벳=행"으로 잘못 적혀 있다.** 그대로 믿지 말 것.

코드 반영: `schema.ALPHABET_AXIS = "col"`, `schema.FAN_BAND_AXIS = "row"`

**팬 송풍 방향 (2026-07-31 정정)**: **호기·위치별로 다르다** (§3.3 참조).
- 트레이 **아래** 팬 = **아래→위 상향** (전 호기 공통)
- 트레이 **위(지그)** 팬 = **위→아래 하향** (4·5호 확인 / **2·3호 미확인**)
- 2026-07-30에 "위→아래 하향"으로만 적었던 것은 **4·5호 윗팬만 본 것**이었다.
  4·5호는 윗팬(하향)과 바닥팬(상향)이 **트레이 중간에서 충돌**하는 구조 → F4 "허브
  정체점" 정황은 이 상하 충돌 정체면으로 재해석해야 한다.

### 3.3 ★★ 호기별 기류 구조 (2026-07-31 사용자 확인) — "전 호기 동일" 뒤집힘

> F 그룹(팬 서명)은 이제 **호기별로 분리해 분석**해야 한다. 전 트레이를 뭉쳐 4-5-4로
> 검정한 것이 "팬 예측 3/3 불일치"(V7)의 유력한 원인이다.

**단면 구조 (위→아래 적층):**
```
┌────────────────────────────┐
│  윗팬 (지그 위)   ↓ 하향송풍   │  4·5호: 4-5-4(13개) / 2·3호: 미확인
├────────────────────────────┤
│  포고핀 + 채널 보드            │  ← 측정 접촉층(프로브). 접촉 이상 = 위치별 측정 아티팩트 원
├────────────────────────────┤
│  트레이 (144셀)               │
├────────────────────────────┤
│  바닥팬 (트레이 아래) ↑ 상향송풍 │  4·5호: 4×4(16개) / 2·3호: 6×6(36개)
└────────────────────────────┘
```

**호기별 팬 구성:**

| 호기 | 윗팬(지그 위, ↓하향) | 바닥팬(트레이 아래, ↑상향) | 추가 외기 |
|---|---|---|---|
| **2·3호** | **미확인**(있을 것으로 추정) | **6×6 = 36개** | **앞뒤**(세로/행축) |
| **4호** | **4-5-4 = 13개** | **4×4 = 16개** | **행1쪽 모서리**(세로축) |
| **5호** | 4-5-4 = 13개 | 4×4 = 16개 | **행12쪽 모서리**(세로축) |

**외기 방향 — 좌표 매핑 (★2026-07-31 확정, 2차 정정)**

> 1차 정정: 최초엔 "측면"이라는 표현 때문에 4·5호를 가로(A~L)축으로 예측했으나,
> 사용자가 "4호=1번쪽 모서리, 5호=12번쪽 모서리"로 정정 — 숫자 1~12는 이 프로젝트에서
> **세로(행)축 전용**이라 4·5호 외기는 **세로(행)축**.
> 2차 정정(같은 날): 2·3호는 **가로(A~L)축**이지만 고정이 아니라 **연(bay)에 따라
> 회전**한다 — 아래 참조. 트레이 방향은 모든 호기에서 동일(탑다운 아이콘 확인).

| 호기 | 진입 | 좌표축 | 예측 냉각 구배 |
|---|---|---|---|
| **4호** | **행1쪽 모서리**에서 진입 | **세로(행 1~12)** | 행1 차갑고 행12로 갈수록 따뜻 |
| **5호** | **행12쪽 모서리**에서 진입 | 세로(행 1~12) | 행12 차갑고 행1로 갈수록 따뜻 (4호 반전) |
| **2·3호** | **둘 사이 공유 복도**에서 진입 | **가로(A~L)** — 단, 고정 아님 ↓ | 아래 "회전풍" 참조 |

**2·3호 "회전풍" 구조 (2026-07-31 확인)**: 2·3호 사이 복도의 바람이 **연(bay,
1~14)의 위치에 따라 트레이를 때리는 열이 바뀐다** — 1연 근처는 A열을, 14연(끝
연)에 가까워질수록 L열을 때린다. 즉 "2호=A축·3호=L축" 같은 호기별 고정 배정이
아니라, **같은 호기 안에서도 연에 따라 콜드스팟이 A→L로 회전**한다.
→ 이 때문에 연을 다 뭉쳐서 호기 하나의 col_slope 를 구하면 회전 때문에 **상쇄돼
약하게** 나온다(아래 실측치가 정확히 이 패턴). **연별로 쪼개야** 신호가 보인다 —
`fan.charger_col_rotation_by_bay()`.

**바닥 팬 배치 (2026-07-31 확인)**: 4×4(4·5호)·6×6(2·3호) 전부 **트레이를 꽉 채우게
균등 배치**(한쪽으로 쏠려 있지 않음) — "바닥 팬격자가 특정 셀에 몰려서 8셀 이상을
만든다"는 가설의 기하학적 근거가 약함(아래 실측 기각과 일치).

```
        A ───────────────→ L      (2·3호: 이 축을 복도바람이 때리되, 어디를 때리는지는
      1 ┌────────────────┐        연 위치에 따라 A→L로 회전)
        │                │
        │                │
     12 └────────────────┘
      세로(행) = 4·5호 외기가 들어오는 축(행1↔행12, 고정)
```

**★ 2026-07-31 실측 확정 (`fan.charger_directional_profile`, 실 랏 1개, t_ocv2 기준,
전체 연을 뭉친 값)**:

| 호기 | 세로(행) 기울기 | 직선성(r) | 가로(열) 기울기 | 직선성(r) |
|---|---|---|---|---|
| 2호 | +0.0157 | +0.224 | +0.0132 | +0.262 |
| 3호 | +0.0096 | +0.310 | −0.0010 | −0.033 |
| **4호** | **+0.0280** | **+0.710** | −0.0078 | −0.257 |
| **5호** | **−0.0272** | **−0.706** | −0.0029 | −0.093 |

**4·5호는 세로축에서 크기 거의 같고 부호만 반대(예측대로 거울상) — 실측으로 확인됨.**
2·3호는 가로축이 전체 평균으로는 약하게 나오는데(r≤0.26), **회전풍 가설이 맞다면
당연한 결과**(연마다 반대 방향으로 상쇄) — `charger_col_rotation_by_bay()` 로
연별 재검정 필요(아직 실 데이터 미실행). EOF 모드1 설명력은 16~18%로 낮아 호기
효과가 실재하되 지배적이진 않음.

**분석·코드 함의:**
1. `schema.FAN_BANDS`(4-5-4)는 **4·5호 윗팬 전용**. 2·3호(바닥 6×6)엔 부적용 → 코드 재검토 필요.
2. **호기별 분리 지문 검증** — 세로축 대칭은 확인됨(위 표). 남은 것: 6×6 vs 4×4 주기성 자체.
3. **8개 이상 셀 가설은 기각됨**(2026-07-31 실측): E5·E8·H5·H8(안쪽 4×4 꼭지점)이 4·5호
   에서만 강할 것으로 예측했으나, **6×6 호기인 3호가 오히려 가장 강했다**(배율 3.47 vs
   4호 2.77·5호 2.82·2호 0.96) → "바닥 4×4 팬격자 아티팩트" 가설 기각, 원인 미상.
   **바깥 꼭지점(A1·A12·L1·L12)은 배율 7.7~11.3배로 더 크고**(세로축 구배보다 3~4배
   큰 효과), **2호만 부호가 반대**(−0.49, 나머지는 +1.1~1.3) — 2호가 왜 다른지 미확인.
4. **연·단(랙 위치) 교란 미배제**: 세로축 구배가 호기 자체 때문인지, 그 호기 트레이들이
   특정 단(높이)에 몰려서인지 아직 미분리 — `tier_<key>` 로 교차검증 필요.
4. **패턴 유형(링/역링/무구조 48.5/36.4/15.1)이 "무작위 트레이"가 아니라 "호기"로
   결정될 가능성** → 호기별 층화로 확인. 맞으면 자리효과 38.3%가 "호기별 보정 가능"으로 바뀜.
5. **호기 식별 = 박스 컬럼으로 확정**(§2.3d 사실 3, `schema.charger_from_box`). 남은
   **미확인**: 2·3호 윗팬 유무(사용자 확인 대기), `#MP1-1`=1호 여부.

## 4. 판정 로직 (현행)

```
docv7 = PRVT1 − PRVT3   (또는 Delta OCV #07 컬럼)
트레이별 docv7 의 mode 산출 → (셀 docv7 − tray mode) > 0.8 mV → 불량(E)
```

- **★Label(A=양품/E=불량)은 이 로직으로 만들어진 것 → 순환 논리.**
  라벨 대비 성능은 "진짜 정확도"가 아니라 "현행 로직과의 일치도"일 뿐이다.
- mode는 값 양자화 때문에 불안정 (타 랏에서 표본 소폭 변경만으로 판정 16셀 뒤집힘 실측).
