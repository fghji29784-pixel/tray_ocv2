# 시각화 구현 계획 — "활성화를 모르는 사람도 납득하는 그림"

> 목표: 활성화공정을 전혀 모르는 청중이 그림만 보고
> **"어? 이건 판정에 영향을 끼치겠는데?"** / **"아 이건 상관없구나"** 를
> 스스로 판단할 수 있게 만든다.
>
> 전제: `docs/03_viz_guidelines.md` 의 R1~R10 을 모두 따른다(제목=결론, 부제=읽는 법,
> 판정기준 대비 % 병기 등). 이 문서는 그 위에 **"판정 영향도를 어떻게 보여줄 것인가"**
> 를 추가로 규정한다.

# 0. 설계 원칙 5개 (이 문서의 핵심)

## ★ 원칙 1 — 세로축은 반드시 "판정"으로 끝난다

비전문가에게 **중간 물리량은 의미가 없다.** 반드시 판정 결과까지 끌고 가야 한다.

| ❌ 이렇게 끝내면 안 됨 | ✅ 이렇게 끝내야 함 |
|---|---|
| "위치별 온도 편차 히트맵" | "이 자리는 평균보다 **N배 더 자주 불량 판정**됩니다" |
| "상관계수 0.70" | "발열이 크면 자리별 편차가 커지고 → **판정 기준의 X%** 를 잠식합니다" |
| "분산의 38%가 위치 성분" | "값 차이의 38%가 자리 탓 → **지금은 이걸 하나도 보정 안 하고** 판정합니다" |

## ★ 원칙 2 — "같은 것을 두 조건에서" 보여준다

비교 없는 절대값은 해석 불가. 모든 핵심 그림은 **대조군**을 갖는다.

- I3: 같은 크기 불량 × 다른 위치 → 검출률 차이
- L6: 같은 데이터 × 무작위 절반 → 두 지도 일치
- F3: 발열 적은 단계 × 발열 큰 단계 → 불균일 차이
- E8: 값 차이 구성 × 현재 보정하는 것(=없음)

## ★ 원칙 3 — "우연이었다면 이렇게 보입니다" (null 비교)

비전문가는 **"이게 대단한 숫자인가?"** 를 모른다. **무작위 대조**를 나란히 두면
설명 없이도 알 수 있다.

- L6 상관 0.977 옆에 → 위치를 섞었을 때의 산점도(구름 모양, r≈0)
- I3 검출률 옆에 → 무작위 기대선
- 꼬리 일관성 0.894 옆에 → 무작위 기대치 0.01

## ★ 원칙 4 — 인과 사슬에서 "지금 어디"인지 표시

각 그림 하단에 **작은 사슬 스트립**을 붙여 이 인자가 어디쯤인지 보여준다.

```
[원인]        →  [값이 달라짐]  →  [판정이 흔들림]
 발열·냉각        docv7 편차        불량 검출률
   F3               E8·L6              I3
   ●                 ○                  ○      ← 현재 그림 위치를 ● 로
```

이게 있으면 "온도 그림"과 "판정 그림"이 **같은 이야기의 다른 장면**임을 이해시킬 수 있다.

## ★ 원칙 0.6 — "정규화" = 트레이 mode 차감 (median → mode 전환)

이 문서에서 이후 등장하는 **"정규화(normalized)"는 전부 "같은 트레이 내 mode(최빈값)를
뺀 값"**을 의미한다. 기존 `fields.tray_delta` 기본값(`stat="median"`)에서
**`stat="mode"`로 전환**한다.

- **왜 median이 아니라 mode인가**: 실제 판정 로직(`JUDGE_OFFSET_MV` 기준선)이 트레이
  mode 기준이므로, 진단도 판정과 같은 기준으로 봐야 "지금 로직이 실제로 보고 있는 것"을
  그대로 재현한다.
- **mode의 위험(경고, 미해결)**: mode는 분해능 양자화 때문에 표본이 조금만 바뀌어도
  값이 튈 수 있다(과거 랏 문서에서 22°C 필터만 바꿔도 16셀 판정이 뒤집힌 사례 있음).
  완화책: ① bin 폭을 변수마다 Freedman–Diaconis 규칙으로 자동 결정(단, `docv7`처럼
  실제 판정에 쓰이는 값은 `JUDGE_MODE_BIN_MV=0.01` 고정 유지), ② `fields.py`에 median
  버전과 mode 버전을 **나란히 비교하는 민감도 검증**을 추가해 두 통계가 크게 갈리는
  트레이가 있는지 확인한다. **아직 코드 미반영 — 구현 순서 1번(6.3 참고).**
- **"정규화"와 "스케일 통일"은 별개다.** 스테이지마다 절대 스케일이 다른 문제
  (예 OCV#02 진폭 ±5.96mV vs docv7 ±0.048mV)는 정규화(=mode 차감)로 해결되는 게
  아니라 **그림별 개별 색 스케일**로 해결한다. 아래 S1 참고.

## ★ 원칙 5 — 판정 영향도 배지를 모든 그림에 단다

우상단에 고정 위치 배지. 한눈에 스캔 가능하게.

| 배지 | 의미 | 색 |
|---|---|---|
| 🔴 **영향 큼** | 판정 결과를 실제로 흔든다 (검증됨) | `C["high"]` |
| 🟠 **영향 있음** | 값에는 영향, 판정 영향은 간접 | `C["high_soft"]` |
| ⚪ **영향 없음** | 확인했으나 무관 (정직성 확보) | `C["neutral"]` |
| ⚫ **판정 불가** | 데이터로 결론 못 냄 (한계 명시) | `C["accent"]` |

> "팬 위치를 의심하게 된 계기가 OCV 지문이었다"는 사실 자체를 발표에 그대로 노출한다.

### 장 1 — `S1_OCV_원본_갤러리.png`
**제목**: "각 단계 OCV 절대값은 그날의 SOC·계측기 스케일에 따라 다릅니다"
**부제**: "패널마다 색 스케일이 다릅니다(스케일이 원래 다른 값이라). 자리 자체의 무늬보다

### 장 2 — `S1_OCV_정규화_갤러리.png`
**제목**: "트레이 mode를 빼고 보면, 거의 모든 단계에서 같은 자리 무늬가 반복됩니다"

**구성**: 장 1과 동일한 10패널 격자. 각 서브패널 = `position_field(mean)` on

(정규화 이후에도 단계별 진폭 자체는 물리적으로 다름 — 예: 중간 OCV 공통무늬
진폭 수 mV대 vs docv7 진폭 0.05mV대. 공유 스케일로 억지로 맞추면 왜곡).
**핵심 주석**: "10개 중 N개 단계에서 같은 위치가 반복해서 튑니다 — 우연이 아닙니다"

### 장 3 — `S1_온도_원본_갤러리.png`
**제목**: "온도도 단계별 절대 수준은 다르지만, 자리 자체의 패턴이 있는지 봅니다"
**부제**: "여기 포함된 단계는 LCI·충전1~7·방전1~7·OCV온도1~7·전용PRVT온도1~3
전부입니다 — 일부만 골라 보여주지 않습니다."

**구성**: 전체 온도 계열 서브패널 격자(약 5행×6열, THERM_STEPS 전체 ~26개).
각 서브패널 = `position_field(mean)`, **원본 온도값(mode 차감 전)**.
색 스케일 기본값은 **서브패널별 독립**(자기발열량이 단계마다 0.7~8.8°C로 10배 차이나므로
S1-OCV와 같은 이유). 필요시 공유 스케일 버전은 보조 그림으로 별도 제공 가능(조정 가능).

### 장 4 — `S1_온도_정규화_갤러리.png`
**제목**: "온도에서도 트레이 mode를 빼면 자리 무늬가 반복됩니다"
**부제**: "장 2(OCV 정규화)와 나란히 놓고 비교하세요 — 같은 자리가 튀는지가 핵심입니다."

**구성**: 장 3과 동일한 전체 온도 계열 격자. 각 서브패널 = `tray_delta(value,
stat="mode")` 의 `position_field(mean)`.

> **왜 이전 초안엔 "충전7·방전7·OCV온도7"만 예시로 있었나**: 설명을 짧게 하려던
> 축약이었을 뿐, 실제 구현 계획이 아니었다. 실제 구현(장 3·4)은 **충전1~7·방전1~7 전

**데이터**: `fields.position_field()`, `fields.tray_delta(..., stat="mode")`
**⚠️ 미해결**: 장 3·4의 색 스케일 기본값(서브패널별 독립)은 이번 설계에서 확정한

# 7. 검증 방법

각 그림은 **합성 데이터(정답을 아는 상태)로 먼저 검증**한다 — 지금까지 코드 검증에
써온 방식 그대로.

- V3b: 합성 데이터는 위치 효과를 균일하게 설계 → **평평하게 나와야 정상**.
  실데이터에서만 들쭉날쭉해야 함. (그림이 실제로 차이를 그려내는지 확인)
